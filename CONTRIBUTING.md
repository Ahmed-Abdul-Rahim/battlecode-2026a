# Contributing

Three of us, no fixed ownership: **assigning yourself an issue is how you claim work.**

## Workflow

1. Pick or open an issue (forms: *Feature*, *Bug / error*, *Experiment*). Add an `area:*` label and assign yourself.
2. Branch from `league`: `feat/<topic>`, `fix/<topic>`, or `exp/<topic>` for experiments.
3. Commit with Conventional Commits: `feat(path): greedy danger tier`, `fix(bot): don't block respawn`, `exp(brain): …`.
4. Before pushing (the pre-push hook runs most of this):
   ```powershell
   cargo fmt --all; cargo clippy --workspace --all-targets -- -D warnings; cargo test --workspace
   bctools sync                     # if you touched crates/
   ruff check .; ruff format .; pytest -q
   bctools gate main                # if behaviour changed
   ```
5. Open a PR with the template filled in (gate numbers, fuel, papers.md IDs). **One approval** from a teammate, CI green, then merge (squash).

Branch protection isn't available for private repos on GitHub Free, so the "one approval + green CI" rule is ours to keep. If someone gets GitHub Pro/Team, turn on required checks for `main`.

## Where code goes

- Decision logic, pathing, codecs: **`crates/`** (SDK-free, host-tested). Add tests next to the code.
- SDK calls and the per-turn wiring: **`bots/main/src/*.rs`**.
- Never edit `bots/main/src/bc_*/` — it's generated by `bctools sync` (cambc forbids path dependencies in the bot's `Cargo.toml`).
- New features for learned heads: edit `ml/features/schema.yaml`, run `python ml/features/gen.py`, then extend `bc-brain/src/features.rs`.
- Memory layouts: `bc-core/src/memory.rs` **and** `docs/memory-layout.md` together; bump the version byte.

## Fuel discipline

Read [docs/fuel-budget.md](docs/fuel-budget.md). Rules of thumb: no full-map loops in guest code per turn, no `HashMap` in hot paths, cache SDK queries that don't change, keep telemetry inside `cambc::debug_block!`. Check `bctools summary` → `fuel_exhausted_turns` must stay 0.

## Hard rules

- **Platform access (agreed by the team for the league loop):** the lead PC may read the platform
  (`cambc ladder`, `matches list/summary/download`). Uploads happen only through `harness/league.py`:
  `--auto-submit` on the one lead PC (at most every 3 h, only after a ladder loss or a benchmark gain,
  auto-revert if the ladder win rate drops), or `scripts/train.ps1 submit` by a human. Never run
  `cambc submit` or `match-groups` by hand.
- Don't hand-edit `league/*.json` or `bots/main/src/pack/pack.bin`: the daemons own them.
- Don't tune parameters against `maps/heldout/`.
- Cite a [papers.md](docs/papers.md) ID for any technique you introduce; add the paper (with venue rank and date checked) if it's new.
